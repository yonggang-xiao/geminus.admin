# 操作审计

模块可以通过配置增加动作和白名单提交内容，无需在每个控制器中拼接日志或写审计表。

## 业务需求

- 具有 `operation-audit.view` 权限的账号可以在后台查看操作审计，通过操作者、对象下拉框及日期选择器、结果筛选记录；显示时间按查看者的时区格式化，筛选日期按 UTC 计算。
- 操作审计只记录已登录用户的后台写操作。登录记录由 Shield 管理，密码登录、魔法链接及 Microsoft 登录不写入操作审计表；邮件投递有独立的发送日志。
- 审计数据不保存完整请求体、密码、令牌或查询字符串；已配置操作只保存受限的白名单提交字段，不代表实际生效值。

## 实现设计

**记录范围。** 全局响应后过滤器将已认证的后台 POST/PUT/PATCH/DELETE 请求写入 `operation_audit_logs`。记录操作者、HTTP 方法、对象类型及标识、请求路径、结果、IP、浏览器 User-Agent（最长 512 字符）与 UTC 时间；角色、权限和邮件模板路由额外记录首个字符串对象名（最长 32 字符）。CSRF、权限等前置过滤器拒绝的请求、未认证后台写请求及抛出异常的请求不会记入操作审计。

**配置采集。** 路由解析后、业务执行前，过滤器按实际控制器、方法及 HTTP 方法匹配配置，采集表单或 JSON 的顶层白名单字段及配置允许的上传文件元数据。已配置操作使用声明的对象类型和路由参数，创建时没有对象 ID 则为空；不从提交值或跳转地址推断对象。动作列显示稳定的业务动作，可展开“提交内容”查看受限摘要；未配置操作和历史记录继续显示基础信息。Admin 为有安全标量提交字段的内置功能提供配置，公告模块提供创建、编辑和附件上传示例。

**结果判定。** HTTP 错误状态记为 `failed`，2xx 记为 `success`；后台写操作的 3xx 重定向优先读取本次新增或更新的反馈：`alert.type=success` 记成功，`alert.type=danger`、`error` 或 `*_errors` 记失败，且失败优先。通过反馈内容和 CI4 Flashdata 生命周期标记区分本次反馈与旧反馈；本次将旧反馈重新写入时，即使内容相同也参与判定。若没有明确反馈，或仅有未更新的旧反馈，仍记为 `redirected`，不能推断业务成败。

语言选择通过隐藏的 `_operation_audit_result` Flashdata 提供明确结果：偏好保存成功记为 `success`，保存返回失败记为 `failed`，不产生可见提示。该反馈同样遵循旧反馈忽略及失败优先规则。

## 配置接入

后台底座与业务模块在各自的 `Config/Registrar.php` 中声明 `OperationAudit()`，向 [审计配置](../admin/geminus/Admin/Config/OperationAudit.php) 追加 `operations` 定义列表。复用 CI4 配置发现，无需修改底座或业务控制器。

| 部分 | 职责 |
| --- | --- |
| 模块配置 | 声明控制器方法、HTTP 方法、动作、对象路由参数和字段白名单 |
| 采集组件 | 按配置提取字段，排除敏感字段并执行大小限制 |
| 审计过滤器 | 获取请求与认证上下文，调用采集组件，沿用结果判定并写入日志 |
| 审计表和页面 | 保存动作和提交摘要，在动作列展开提交内容 |

采集组件接收显式的配置和输入，不自行获取全局请求或查询业务数据库。受控输入在路由已解析且业务执行前采集，仅保存在本次请求中，不放入 Session 或共享服务。

以实际解析后的完整控制器类、方法和 HTTP 方法匹配，不按语言前缀或 URL 字符串匹配。重复或非法配置应报告错误，不静默覆盖。

```php
public static function OperationAudit(): array
{
	return ['operations' => [[
		'controller' => 'Modules\\Announcements\\Controllers\\Announcements::update',
		'methods' => ['POST'],
		'action' => 'announcement.update',
		'object' => ['type' => 'announcement', 'route_parameter' => 0],
		'fields' => ['title'],
	]]];
}
```

| 配置项 | 契约 |
| --- | --- |
| `controller` | 完整控制器类名与方法，以 `::` 分隔；不包含路由参数 |
| `methods` | 明确的 POST/PUT/PATCH/DELETE 写请求方法，不允许 GET 执行写操作 |
| `action` | 稳定的动作标识，如 `announcement.update`；不是 HTTP 方法，也不是权限名称 |
| `object.type` | 模块声明的稳定对象类型，不从路径猜测 |
| `object.route_parameter` | 已解析路由参数的索引，从 0 开始；无对象 ID 时省略 |
| `fields` | 非空的精确字段白名单；未声明字段直接忽略，不支持“记录全部”的通配符；空列表属于非法配置 |

示例只记录提交的标题，不记录正文。页面直接显示稳定动作标识，不增加动作翻译配置。[公告 Registrar](../admin/modules/Announcements/Config/Registrar.php) 已接入创建、编辑和附件上传，发布及附件删除继续基础审计。[后台 Registrar](../admin/geminus/Admin/Config/Registrar.php) 只声明白名单非空的内置操作：

| 内置操作 | 提交字段 |
| --- | --- |
| 语言选择、个人偏好 | `language`；个人偏好还记录 `timezone` |
| 用户编辑 | `role`、`status` |
| 角色创建、编辑 | `title`、`description`；创建还记录 `name` |
| 权限创建、编辑 | `description`；创建还记录 `name` |
| 邮件设置 | `protocol`、`SMTPPort`、`SMTPCrypto` |
| 邮件模板编辑 | `subject` |
| Microsoft 登录设置 | `enabled` |
| Microsoft 绑定审批 | `user_id`；对象 ID 为路由中的申请 ID |
| 访问令牌创建 | `name`、`expires`，不记录生成的令牌 |

用户名、邮箱、邮件正文、SMTP 主机和账号、Microsoft 租户和客户端标识不在内置白名单中。没有可采集字段的操作不声明配置，继续记录基础信息：包括用户创建、导入和邀请，角色权限数组提交，测试邮件发送，邮件模板重置，Microsoft 连接、拒绝和撤销，头像、密码、令牌撤销及通知打开。

动作标识最长 128 字符，对象类型最长 64 字符，对象 ID 最长 32 字符；字段名最长 64 字符，普通字段只允许字母、数字、下划线和连字符，且不能以数字开头。字段白名单不允许重复项。同一控制器方法的同一 HTTP 方法只能有一份定义。

上传文件元数据使用 `文件字段.name`、`文件字段.size`、`文件字段.type`，例如 `fields => ['file.name', 'file.size', 'file.type']`。只从 multipart 上传对象读取原文件名（去除路径部分）、字节数、客户端声明的 MIME 类型，不读取文件内容、临时路径或存储路径。客户端类型不是服务端识别类型，不能用作上传安全依据。普通表单和 JSON 不能伪造这些字段；未选择文件或上传错误时不保存元数据。名称和类型同样受字符串长度及摘要大小限制。附件上传失败但已接收到文件时，仍可记录提交元数据，不能据此认定附件已保存。

创建请求尚无对象 ID 时保持为空，不从提交内容或重定向地址推断新 ID。批量操作不展开为逐对象审计。

邮件模板保存和重置沿用对象类型 `templates`，Microsoft 绑定审批和拒绝沿用 `requests`，避免同一对象被筛选为不同类型。模板对象 ID 只包含模板类型；模板语言由完整请求路径区分，不组合多个路由参数作为对象 ID。

## 提交内容与限制

POST 表单读取提交字段，PUT/PATCH/DELETE 的 URL 编码表单读取原始表单输入；JSON 及 `+json` 类型使用 JSON 对象解析。只采集顶层标量字段，不转换为业务验证后的类型。非 POST multipart 文件表单不提供字段采集支持。

提交字段表示操作意图，不等同于数据库最终值。字段可能未通过验证、被忽略、经过转换，或与原值相同；界面将这部分标为“提交内容”，不能称为“变更前后”或“已生效内容”。新增采集配置不解决静默重定向的结果未知问题，也不证明实际持久化或异步任务完成，不能配置“默认成功”来替代真实结果。

- 密码、令牌、CSRF 值、密钥、验证码及会话标识直接不记录，系统禁止规则优先于字段白名单。个人信息按最小必要原则排除；敏感词检查不能替代白名单审查。
- 不保存文件内容、完整请求体、请求头或查询字符串。数组、对象标记 `complex_value`，非有限数值标记 `invalid_value`；非法 JSON 或非对象根值标记 `invalid_json`，不保存原值。
- 全局限制：最多 32 个字段、每个字符串最多 256 个字符、摘要编码后最多 8 KiB。超限标记截断或省略，不截断 JSON 字节串。
- 摘要的 `fields` 保存字段值，`omitted` 保存省略原因，`truncated` 保存截断字段名，`limited` 表示达到整体限制；为状态标记预留空间，采集可能在 8 KiB 之前停止。缺失字段不记录；敏感字段不保留值或占位内容。
- 使用结构化 JSON 和安全数据库接口；展示统一转义，错误日志不包含原始提交内容。
- 操作者取自认证上下文；提交值和对象定位不能作为授权依据。认证、授权和 CSRF 仍由现有机制处理。

审计表以可空的 `operation` 保存业务动作，以 JSONB `submission` 保存提交摘要。HTTP 方法继续由 `action` 独立保存。列表优先显示动作，未配置时回退 HTTP 方法；展开区域显示提交内容。历史记录不回填，表结构由迁移管理。

## 运行约束

部署前运行 `php spark migrate --all`。审计写入失败时会记录服务器错误日志，但不改变原请求的响应。审计数据包含 IP、用户标识和 User-Agent，请限制数据库访问，并按业务合规要求制定保留及清理策略。

摘要采集失败时记录不含提交内容的错误日志，并保留基础审计记录。采集数据只存在于单次请求，审计写入不与业务事务原子提交，不提供合规审计或可靠投递保证。

底座不提供多种脱敏模式、复杂字段采集、Events、结果证据分类或实际变更追踪。

## 模块测试要求

- 两个模块仅添加配置即可采集动作、对象及白名单字段，不增加控制器记录代码。
- 不同语言路径、表单和 JSON 正确匹配；未配置操作保留基础记录，重复及非法配置有诊断。
- 敏感及非白名单字段不入库，复杂值、非法 JSON 和超限内容有省略或截断标记。
- 新旧记录正常展示，提交内容不被标为实际变化；现有结果判定、查看权限和安全转义保持有效。
- 请求及 worker 复用不串用数据；采集或存储失败不改变响应，不泄漏输入，认证、授权及 CSRF 回归通过。
