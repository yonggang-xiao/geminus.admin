# 用户管理

用户管理用于创建后台账号、调整访问角色，以及导入和导出用户。使用具有 `users.manage-admins` 权限的账号登录后，打开 `/{locale}/admin/users`（本地英文页面为 `https://localhost/en/admin/users`）。当前权限配置中，`superadmin` 组具有此权限。

## 查找与维护账号

- 列表按用户名或邮箱搜索，每页显示 20 人；点击用户名、邮箱或创建时间表头可切换升序、降序。清除筛选可恢复完整列表。
- “创建用户”填写用户名和邮箱；用户名为 3–30 位英文字母、数字或点，邮箱最长 254 字符。邮箱查重不区分大小写，已有邮箱不会被覆盖。
- 新账号默认属于 `user` 组，没有已知的本地密码，也不会自动绑定微软身份。创建账号本身不授予后台管理权限。
- 列表中的“编辑”可修改其他普通账号的用户名、邮箱、`user`/`admin` 组和正常/封禁状态；用户名和邮箱始终必填。不能通过此页面修改自己的账号、现有 `superadmin` 或属于其他组的账号。修改邮箱会更新 Shield 的邮件身份，不会修改本地密码或自动更换微软身份绑定。需要管理权限时，可把用户设为 `admin`。封禁或改组不保证立即结束已经建立的会话。

## CSV 导入

从用户列表下载“CSV 模板”，填写 UTF-8 编码的 CSV 文件。第一行必须是以下表头，且只有这两列：

```csv
username,email
alice,alice@example.com
bob,bob@example.com
```

文件扩展名必须为 `.csv`，实际 MIME 类型须为文本或 CSV；文件不得超过 1 MB，最多包含 500 条非空数据行。超出限制或表头不符时，整个文件会被拒绝，不会开始创建用户。

上传后显示逐行结果（行号、邮箱、结果、原因）：

- **已创建**：通过与单独创建相同的字段验证，创建账号并加入默认 `user` 组。
- **已跳过**：邮箱已存在，或同一文件前面的有效行已使用该邮箱；原账号不会被修改。
- **失败**：用户名或邮箱无效、用户名已存在，或该行无法保存。其他有效行仍会继续处理。

导入报告只在本次导入后显示，请当场核对结果。导入不接受角色、密码或微软身份列，也不会凭邮箱把账号与微软身份关联。

## CSV 导出

点击“导出 CSV”下载当前搜索条件下的用户；排序与列表保持一致。导出的是全部匹配用户，不仅是当前页，每次最多 10000 人；超过时需要缩小搜索范围。文件只包含 `username,email` 两列，不包含密码哈希、令牌或微软身份。为避免电子表格把单元格当作公式执行，以公式字符开头的值在导出时会被转义。

## 微软登录与验证

用户可以在已有本地登录凭据时自行登录并发起微软账号绑定；没有本地登录凭据的用户可以通过微软登录入口提交访问申请，由管理员线下核实身份后审批绑定到已有后台账号。普通 `user` 组账号也可以获批绑定，但绑定不会自动提升其角色；微软邮箱相同不构成自动绑定依据。详细规则见 [Microsoft 登录](microsoft-login.md)。

在仓库根目录运行用户管理相关测试：

```sh
docker compose -f docker/docker-compose.yaml exec -T geminus-admin vendor/bin/phpunit --testsuite App --filter 'UsersTest|UserCsvImportTest' --no-coverage
```

自动化测试覆盖账号创建、筛选与导出、导入逐行处理、权限和 CSRF 等路径；真实 HTTP 文件上传仍需在浏览器中用受控 CSV 完成一次验证。
