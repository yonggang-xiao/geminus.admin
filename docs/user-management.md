# 用户管理

## 业务需求

- 用户列表、权限查看和导出需要 `users.view`，创建、CSV 模板和导入需要 `users.create`，编辑、邀请和微软绑定管理需要 `users.edit`。管理 `admin` 账号或分配 `admin` 角色还需要 `users.manage-admins`；该权限不用于普通用户操作，也不替代基础操作权限。新建账号默认没有后台管理权限，也不会自动获得本地密码或微软身份绑定。
- 邀请由管理员主动发起并异步发送，用户自行申请有时效性的登录链接；创建和导入账号不会自动发邀请。管理员可查看最新一次邀请的发送状态，失败后可重试。
- 用户管理只处理可编辑的普通账号，不允许通过编辑页面修改自己、已有 `superadmin` 或属于多个组的账号。管理权限通过角色授予；微软身份必须单独绑定或审批。

## 实现设计

### 查找与维护账号

- 列表按用户名或邮箱搜索，不区分大小写，每页显示 20 人；点击用户名、邮箱或创建时间表头可切换升序、降序。用户名和邮箱按不区分大小写的值排序，清除筛选可恢复完整列表。具有 `users.view` 权限的账号可在操作列点击“查看权限”，查看列表中任意用户（包括受保护账号）从角色和直接授权获得的当前目录内权限；目录外的原始授权不在此处枚举。创建、导入、编辑和邀请入口按对应操作权限显示。
- “创建用户”填写用户名和邮箱；用户名为 3–30 位英文字母、数字或点，邮箱最长 254 字符。用户名和邮箱查重均不区分大小写，已有账号不会被覆盖。
- 新账号默认属于 `user` 组，没有已知的本地密码，也不会自动绑定微软身份。创建账号本身不授予后台管理权限。
- 对可编辑且未封禁的用户，列表中可点击“发送邀请”。需要先配置发件邮箱并启用魔法链接登录；邮件会引导收件人前往魔法链接登录页，自行申请有时效性的登录链接。操作后提示是否成功入队；列表中的邀请状态按最新一次邀请显示“已入队”“已发送”或“发送失败”，刷新页面可查看队列处理后的状态，失败可再次点击发送。“已发送”表示邮件服务器接受发送，不保证收件箱最终投递。创建或 CSV 导入账号不会自动发送邀请。
- 列表中的“编辑”可修改其他普通账号的用户名、邮箱、非 `superadmin` 单一角色和正常/封禁状态；用户名和邮箱始终必填。不能通过此页面修改自己的账号、现有 `superadmin` 或同时属于多个组的账号。修改邮箱会更新 Shield 的邮件身份，不会修改本地密码或自动更换微软身份绑定。需要管理权限时，可分配具备相应权限的角色。封禁或改组不保证立即结束已经建立的会话。

### 分配角色

新建角色可在用户编辑页分配；拥有 `users.edit` 但不是超级管理员的账号只能分配自身已有权限覆盖的角色，不能编辑角色授权或用户直接授权超出自身范围的账号。只有 `admin` 角色被视为管理员，编辑已有 `admin` 账号或将普通用户提升为 `admin` 必须额外具备 `users.manage-admins`；`developer` 和自定义角色仍按权限范围判定是否可编辑。微软绑定管理使用同一目标账号保护规则。角色、权限目录、授权规则及新增业务权限的流程见[角色与权限](roles-and-permissions.md)。

### CSV 导入

从用户列表下载“CSV 模板”，填写 UTF-8 编码的 CSV 文件。第一行必须是以下表头，且只有这两列：

```csv
username,email
alice,alice@example.com
bob,bob@example.com
```

文件扩展名必须为 `.csv`，实际 MIME 类型须为文本或 CSV；文件不得超过 1 MB，最多包含 500 条非空数据行。超出限制或表头不符时，整个文件会被拒绝，不会开始创建用户。

上传后显示逐行结果（行号、邮箱、结果、原因）：

- **已创建**：通过与单独创建相同的字段验证，创建账号并加入默认 `user` 组。
- **已跳过**：邮箱已存在，或同一文件前面的有效行已使用该邮箱；原账号不会被修改。
- **失败**：用户名或邮箱无效、用户名已存在，或该行无法保存。其他有效行仍会继续处理。

导入报告只在本次导入后显示，请当场核对结果。导入不接受角色、密码或微软身份列，也不会凭邮箱把账号与微软身份关联。

### 数据库唯一性

PostgreSQL 中 `users.username` 使用 `citext` 和 Shield 原有的唯一键，不区分大小写地查询和查重；混存其他凭据的 `auth_identities.secret` 保持原类型，仅对 `email_password` 身份建立 `LOWER(secret)` 唯一索引。密码哈希与微软身份、访问令牌不在上述邮箱唯一索引范围内。

### CSV 导出

点击“导出 CSV”下载当前搜索条件下的用户；排序与列表保持一致。导出的是全部匹配用户，不仅是当前页，每次最多 10000 人；超过时需要缩小搜索范围。文件只包含 `username,email` 两列，不包含密码哈希、令牌或微软身份。为避免电子表格把单元格当作公式执行，以公式字符开头的值在导出时会被转义。

### 微软登录

用户可以在已有本地登录凭据时自行登录并发起微软账号绑定；没有本地登录凭据的用户可以通过微软登录入口提交访问申请，由管理员线下核实身份后审批绑定到已有后台账号。普通 `user` 组账号也可以获批绑定，但绑定不会自动提升其角色；微软邮箱相同不构成自动绑定依据。详细规则见 [Microsoft 登录](microsoft-login.md)。

## 运行约束

使用具有 `users.view` 权限的账号打开 `/{locale}/admin/users`（本地英文页面为 `https://localhost/en/admin/users`）。迁移不会自动修改存量账号；运行 `php spark migrate --all` 前先排查不区分大小写的标识冲突：

```sql
SELECT lower(username), count(*) FROM users GROUP BY lower(username) HAVING count(*) > 1;
SELECT lower(secret), count(*) FROM auth_identities WHERE type = 'email_password' GROUP BY lower(secret) HAVING count(*) > 1;
```

如有结果，先确认并人工处理重复账号，再运行迁移。

在仓库根目录运行用户管理相关测试：

```sh
docker compose -f docker/docker-compose.yaml exec -T geminus-admin vendor/bin/phpunit --testsuite App --filter 'UsersTest|UserCsvImportTest' --no-coverage
```

自动化测试覆盖账号创建、邀请发送结果、筛选与导出、导入逐行处理、权限和 CSRF 等路径；真实 HTTP 文件上传仍需在浏览器中用受控 CSV 完成一次验证。
