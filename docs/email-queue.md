# 邮件发送与模板

## 业务需求

- 管理员可以向已创建的用户发送邀请，用户收到邮件后通过登录链接申请页面请求登录链接；邀请本身不生成一次性登录令牌。登录链接、账户激活和邮箱验证码邮件也由统一模板管理。
- 具备 `admin.settings` 权限的管理员可以按邮件类型和语言维护主题与 HTML 正文、预览效果并恢复默认模板。模板修改仅作用于之后入队的邮件，不改写已排队的内容。
- 管理员可以查看发送记录、投递状态与失败原因，以便确认邀请是否送达；不能从后台页面读取邮件正文或认证令牌。邮件设置页的测试邮件用于验证发送配置，不计入投递记录。
- 邀请邮件在启用微软登录时提供微软登录入口，并告知未绑定账号需要审批或绑定；关闭微软登录时不展示该说明。

## 实现设计

**服务装配。** [后台 Services](../admin/geminus/Admin/Config/Services.php) 负责邮件模板及队列邮件实例的依赖装配；[应用 Services](../admin/app/Config/Services.php) 通过 `email()` 委托后台的 `queuedEmail()`，启用全局队列邮件实现。全局邮件入口保留共享实例、显式配置和测试替换契约。

**模板与渲染。** 用户邀请及 Shield 的三类认证邮件共用 HTML 邮件外壳。模板按类型和语言存储在 Settings 中；未保存时使用对应语言的默认主题与正文。正文必须保留所需的 `{link}` 或 `{code}`，主题只允许该类型指定的占位符，不允许换行。渲染时转义用户名、链接等动态值，保留管理员编写的 HTML。邀请正文中的 `{microsoftLogin}` 根据 `MicrosoftOAuth.enabled` 填入本地化的微软登录说明及指向当前站点的绝对链接，未启用时替换为空。

**预览。** HTML 编辑页使用带沙盒与 CSP 的 iframe 预览，不能在预览中跳转。`{link}` 使用所选语言对应的当前站点地址：邀请邮件指向申请登录链接的页面，魔法链接邮件指向验证页面并使用不可登录的示例 token。预览中的其他动态字段使用示例值；实际发送时使用真实用户数据和令牌。

**队列与审计。** 普通邮件入 `email` 队列，由任务异步投递；入队时把主题、正文、收件人和邮件类型写入队列载荷。`email_delivery_logs` 记录收件人、主题、任务及邀请用户关联、状态、尝试次数、处理时间与归类后的失败原因，不保存正文；重试成功后清除失败原因。发送记录可按状态及收件人筛选，收件人采用不区分大小写的模糊搜索；队列视图只列出邮件任务，不展示载荷或原始调试信息。失败任务最多尝试三次。邮件设置页的测试邮件仍同步发送，不进入邮件队列和发送记录。

## 运行约束

部署前运行 `php spark migrate --all`。任务调度需每分钟执行 `php spark tasks:run`：Compose 的 `geminus-admin` 容器已通过 cron 提供，非 Compose 部署需自行配置。队列与发送记录页面依赖项目默认的数据库 Queue 后端和应用默认数据库；更换后端或连接时需同步调整查询。队列载荷含正文和认证令牌，应限制数据库读取权限并按需清理过期任务。
