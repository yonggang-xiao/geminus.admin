# 角色与权限

角色与权限用于控制后台各业务模块的访问，不等同于用户账号的登录或微软身份绑定。角色是分配给用户的一组授权；权限是业务路由或代码检查的标识（如 `users.create`）。角色授权矩阵决定角色拥有哪些权限，用户也可以获得直接授权。权限必须由对应业务模块实际检查，添加到目录或授予角色本身不会自动保护页面或操作。

## 管理角色和权限

`superadmin` 可在“系统设置 → 角色与权限”中创建角色（标识由小写字母、数字和连字符组成），编辑角色的显示名称与描述，或创建权限（`domain.ability` 两段式标识）并编辑其描述。角色和权限标识可能被路由及业务代码引用，不能在页面中重命名；需要其他标识时应创建新的角色或权限。具体可用的权限以当前权限目录和业务模块的授权检查为准，不在此文档维护另一份权限清单。

可为非 `superadmin` 角色勾选目录中的已有权限。取消勾选仅针对目录内的授权；若已有通配符覆盖被取消的权限，保存时会提示冲突，目录外的原始授权也不会因取消勾选而自动删除。新权限创建后默认授予超级管理员，其他角色需要显式授权；已有通配符授权覆盖新权限时，该角色也会自动获得对应权限。超级管理员的权限不能在页面中撤销。已有未纳入目录的原始授权不会在目录中作为可勾选权限显示。

## 让业务权限生效

业务模块新增受保护操作时，先在路由或业务代码中检查相应权限，再将权限加入目录并为需要访问的角色授权。角色、权限目录及授权矩阵持久化在 CodeIgniter Settings 中；`AuthGroups` 配置提供尚未保存时的默认值，已保存的整个目录或矩阵优先于配置。若权限目录已通过页面保存，部署新增业务权限后仍需在此页创建权限并为相应角色授权，不能只修改配置默认值。

用户管理页可以为普通账号分配非 `superadmin` 角色；具有用户管理权限但不是超级管理员的账号只能分配自身已有权限覆盖的角色。新建角色后即可在用户编辑页分配。仅添加角色或权限不会自动改变现有用户的角色和会话状态。有关用户编辑和权限查看入口，参见[用户管理](user-management.md)。
