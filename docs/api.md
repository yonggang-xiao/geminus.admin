# API 设计

本文说明后台统一 API 规则，公告发布作为业务模块接入示例。Admin 提供 Token 认证、权限与 scope 检查、限流和 JSON 协议，公告模块提供直接发布接口。

## 业务需求

- 外部系统和自动化程序通过 API 调用已开放的业务能力，使用 Access Token 认证，不依赖浏览器会话。
- 密钥 scope 从用户已有权限中显式选择，权限标识与描述复用现有目录，不另建 API 权限体系。
- Admin 统一实现认证、授权和协议规则；模块声明所需权限并实现业务，不重复通用安全逻辑。
- 用户权限调整后，后续 API 请求与密钥管理页面按最新授权判断，不需重新登录或更换密钥。
- 公告示例支持 OA 发布通知到后台，仅提供发布，不提供查询、更新、删除、附件、批量同步或定时发布。

## 实现设计

### 授权模型

本项目规定 scope 为用户已有权限的显式子集。这是应用约束，Shield 不会自动校验 scope 是否属于用户权限。

| 环节 | 规则 |
| --- | --- |
| 创建密钥 | 从 Settings 的 `AuthGroups.permissions` 目录中筛选 Shield `can()` 允许的具体权限，默认不勾选、至少选一项；服务端拒绝未知、越权及通配符提交 |
| 保存 scope | 将去重后的所选权限交给 Shield `generateAccessToken()`，不复制全部权限，不保存 `*` 或域通配符；账号通配符只用于筛选具体权限 |
| 调用 API | 对模块声明的权限 `$permission`，同时检查当前账号 `can($permission)` 与本次密钥 `tokenCan($permission)`；空 scope、通配符或任一检查失败均返回 403，超级管理员也不例外 |
| 后台展示 | 创建和列表统一使用“密钥权限”，复用目录标识与描述；区分有效、账号未授权、权限未登记和密钥失效，不另起 API 操作名称 |

密钥列表保留名称、有效期、最后使用时间和吊销操作；目录移除的权限保留原标识，历史通配符密钥标记为不可用于本方案的 API。第一版不编辑已有 scope，调整范围需创建新密钥并吊销旧密钥。

密钥只限制 API，不改变账号的后台权限。权限目录不是接口清单，选择权限不代表已有对应 API；新增接口若要求同一权限，已选该权限的密钥也可调用。需要更细粒度时，应统一细分业务权限。权限注册及角色分配见[角色与权限](roles-and-permissions.md)。

### 代码归属与职责

| 归属 | 职责 |
| --- | --- |
| `Geminus\Admin` | 复用 Shield 完成 Token 认证、账号可用性、权限与 scope 检查、权限刷新、限流、密钥管理、JSON 请求与响应及审计接入 |
| `admin/app/Config/` | 注册、装配通用能力，精确配置 API 的会话与 CSRF 例外 |
| 业务模块 | 声明路由、所需权限及审计白名单，实现字段校验、业务对象授权、持久化，以及按业务需要提供的幂等、事务和事件 |

模块通过路由接入 Admin 通用过滤器，不重复认证授权；通用代码接收权限参数，不依赖特定模块或重写 Shield 规则。操作者由认证结果取得并显式传入业务服务，服务与后台页面复用业务规则，不依赖当前会话。业务错误条件由模块决定，Admin 统一 HTTP 表达，不构建万能 CRUD、通用业务幂等或跨模块事务服务。

### 权限调整后的同步检测

scope 不随账号授权自动改写。Admin 每次请求检查最新角色、角色授权矩阵和直接授权，实际有效权限为 scope 与账号当前权限的交集：撤权后拒绝，增权不扩大旧密钥，恢复原授权后有效密钥可再次使用。撤销单一授权来源时，仍须考虑其他角色、直接授权或通配符的覆盖。

变更提交后的新请求必须生效，无需重新登录、换密钥或等待定时同步；Admin 负责缓存失效和长驻进程的授权刷新，不追溯取消已执行中的请求。密钥页面加载时重新计算状态，刷新后与 API 判断一致，不要求实时推送。

### 请求与响应

业务 API 使用 `/api/v1/` 前缀，不带语言路径，通过 HTTPS、JSON 和 `Authorization: Bearer <Access Token>` 调用，仅接受 Token 认证。无效或失效密钥、禁用或删除的账号返回 JSON 401，不重定向登录；不能借用会话或同账号另一把密钥的权限。

`api/v1/*` 统一排除全局会话与 CSRF 要求，并由路径级路由声明守卫保护：未声明 `api:<具体权限>` 完整组合、权限参数为空或使用通配符、多参数的路由返回 JSON 403，不执行控制器。合法路由由组合启用限流与 Token 认证授权；后台表单防护不变，不接受 Cookie 认证或任意来源 CORS。Shield 的 `tokenCan()` 允许 `*`，通用入口须显式拒绝通配符密钥。

带 JSON 请求体的接口须声明 `Content-Type: application/json`，顶层为对象；字段和业务规则由模块定义。成功响应使用 `data`，错误遵循 CI4 `ResponseTrait` 默认的 `status`、`error`、`messages` 结构，`status` 与 `error` 均为 HTTP 状态码。一般错误说明位于 `messages.error`，字段校验错误按字段名放在 `messages` 中。响应固定为 JSON，均设置 `Cache-Control: no-store`。

| HTTP 状态 | 含义 |
| --- | --- |
| 400 | JSON 无法解析或顶层不是对象 |
| 401 | Token 无效或账号不可用 |
| 403 | 路由声明、账号权限或当前密钥 scope 不满足要求，包括通配符密钥 |
| 415 | 要求 JSON 的接口收到其他内容类型 |
| 422 | 字段校验失败 |
| 429 | 超过 API 请求限制，提供 `Retry-After` |
| 500 | 内部处理失败，不暴露异常细节 |

业务成功状态及冲突等错误由模块契约确定；不统一要求所有接口幂等或使用事务。

```json
{
  "status": 422,
  "error": 422,
  "messages": {
    "title": "标题不能为空。"
  }
}
```

### 操作审计

API 写操作接入[操作审计](operation-audit.md)，由 Admin 获取 Token 操作者，模块声明动作、对象及字段白名单。不记录密钥、Authorization 请求头、敏感业务正文或异常堆栈。

审计支持后台和 `/api/v1/` 写操作，API 操作者取自本次 Token 认证结果，JSON 摘要按模块白名单采集；未声明白名单的字段不记录。审计不承担业务幂等，也不保证与业务事务一致。

### 公告接入示例

OA 审核内容后调用 `POST /api/v1/announcements`，成功即发布，不经过草稿审批。[公告模块](example-business-module.md)声明所需权限 `announcements.manage`，账号与密钥均需具有该权限；不能将密钥描述为“仅允许发布”。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `title` | 字符串 | 必填，去除首尾空白后非空，最长 150 字符 |
| `body` | 字符串 | 必填，去除首尾空白后非空，最长 2000 字符；纯文本 |

仅接受上述字段，不转换非字符串值；未知字段返回 422，不接受客户端指定状态、发布时间或操作者。标题与正文复用模块共享规则，禁止 NUL 字符，正文内部空白及换行不额外归一化。

```http
POST /api/v1/announcements
Authorization: Bearer <Access Token>
Content-Type: application/json

{
  "title": "系统维护通知",
  "body": "今晚 22:00 至 23:00 进行系统维护。"
}
```

公告发布不提供幂等或内容去重。每次成功请求都创建一条新公告，包括相同内容的重复或并发请求；不接受来源编号，不返回重放标记或来源冲突。重复公告可在后台删除，但删除不能撤回已发出的通知或用户已经看到的内容。

公告创建与发布状态在同一事务中保存，写入失败全部回滚。服务端设置 UTC 发布时间并传入认证操作者，复用模块发布服务，在最外层事务提交后触发 `announcements.published`。

成功返回 201，包含本次新公告 ID、发布状态和 UTC 发布时间，不回传正文：

```json
{
  "data": {
    "id": 123,
    "status": "published",
    "published_at": "2026-10-12T08:00:00Z"
  }
}
```

通知沿用模块接收人规则并排除发布操作者；每次成功创建的新公告分别触发通知，不改变之前通知的已读状态。通知异常仅记录错误日志，不撤销公告或改变成功响应，无自动重试和可靠投递保证。详见[发布事件与通知中心](example-business-module.md#发布事件与通知中心)。审计摘要仅含 `title`，不记录正文。

## 运行约束

部署时须运行模块迁移。业务模块使用显式资源路由，声明 `api:<权限>` 组合过滤器，例如 `api:announcements.manage`。组合由应用的 `Config\Filters` 统一定义，按顺序执行 IP 限流、认证授权、已认证密钥限流和 JSON 请求格式校验，业务模块不重复列出通用过滤器。应用为 `api/v1/*` 统一配置会话与 CSRF 例外及 `apiRouteGuard` 路由声明守卫，新增同前缀接口无需修改例外清单；路由仍必须声明一个具体业务权限。例外仅覆盖 `api/v1/` 下级路径；裸 `api/v1`（含末尾斜杠）及其他版本仍受会话与 CSRF 保护。例外不扩展到 `api/*` 或其他前缀，不开放匿名调用或公开注册。

通用入口使用 CI4 Throttler，每个 IP 的桶容量为 120，每把密钥的桶容量为 60，均在 60 秒内补满；超过限制返回 429 和 `Retry-After`。缓存服务须正常运行，不能使用不持久化请求间状态的 dummy 缓存。API 请求及密钥页面重新读取授权配置和账号授权，以适配长驻进程。

公告发布服务管理最外层事务，不在其他业务事务内调用。

对接使用专用账号、显式选定权限和带有效期的密钥，密钥保存在安全配置中，不写入源码、浏览器脚本、URL 或普通日志。历史 `*` 密钥不自动转换，须创建明确范围的新密钥；泄漏时立即吊销并更换。

重试遵循模块契约，不默认认为所有写操作可安全重试。公告超时或 500 时先在后台核对是否已发布，不盲目自动重试，否则可能生成重复公告和通知；429 时按 `Retry-After` 重试，401、403、415、422 先处理原因。公告 API 不提供修订接口，修改或删除通过后台处理。

实现验收使用 [README 中的独立测试数据库](../README.md#运行测试)：

- 通用认证、权限和 scope 的失败路径无业务写入，不借用会话或其他密钥，不影响后台 CSRF。
- 密钥创建拒绝非法授权，界面复用权限目录并正确展示有效状态；角色、矩阵及直接授权调整后，同一密钥的下一请求与页面刷新均反映最新权限。
- JSON、响应、限流和审计符合通用契约，不泄漏密钥、敏感正文或异常细节。
- 公告字段边界符合示例契约，相同内容的重复及并发请求各创建新公告，不覆盖后台编辑后的公告。
- 公告写入失败回滚并可重试，事件仅在提交后触发；每条新公告分别通知，已有通知的已读状态不变，投递失败不影响发布结果。
